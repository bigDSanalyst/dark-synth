# A6 — Anchor Content-Binding Fragility (v1.2.6)

**Claim.** Axiom 14 (a green check must never lie) — anchor layer.
**Failure mode.** FM9 (silent pass on partial coverage) + FM11 (fallback success).
**Bug.** At v1.2.6, `tools/anchor.py verify` called `ots verify <records.jsonl.ots>`
without an explicit data argument. Content binding held only because the OTS CLI
auto-detects a sibling data file with the same basename in the same directory.
Empirical baseline: `anchor rc=1` on a clean ledger — but the failure was
`Could not connect to Bitcoin node`, *after* the hash comparison passed. So the
binding existed; it was just held together by filesystem luck, not by design.

Move the `.ots` file to a different directory, or copy only the proof to an
air-gapped verifier, and the binding disappears silently.

**Caught by.** The M10 mutation-battery trial (v1.2.7 audit run):
- Baseline pre-patch: `anchor rc=1` (node error, not hash mismatch — binding was
  accidental)
- Baseline post-patch: `anchor rc=0` (offline, digest + manifest agree)
- M10 tampered: `anchor rc=2  proof digest mismatch: proof says 312a9f39affb4d7f,
  ledger is 01d9965a1dd18fd0`

**Fix.** `tools/anchor.py verify` rewritten to:
1. Call `ots info <proof>` (offline, no Bitcoin node required)
2. Extract `File sha256 hash: <hex>` from the proof's internal digest
3. Compare directly to `sha256(current_ledger)` — path-independent, no sibling
   auto-detect dependency
4. Cross-check `anchor_manifest.jsonl`'s `ledger_sha256` (defense in depth)
5. Return code split: 0 = match, 1 = infrastructure, 2 = content mismatch

**Mutation test.** M10 in the M-battery: tampered ledger → `anchor rc=2`, with the
exact message `proof digest mismatch`. Clean ledger → `anchor rc=0`, block 973378
confirmed. Baseline green, all four mutants (M1, M2, M3, M8) rejected by all three
layers.

**Consequence for Axiom 14.** All three layers (chain, doctor, anchor) now
independently reject tampering. The empirical verdict is `VERIFIED` at every
layer. Before v1.2.7, the anchor layer was `VERIFIED-BY-LUCK`; after, it is
`VERIFIED-BY-DESIGN`.

**Status.** `[P/patched]` + `[run]`
